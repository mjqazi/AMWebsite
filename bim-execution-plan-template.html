BIM execution plan: a practical starting outline.

Before modelling starts, agree what the model is for, which information can be trusted and who reviews the result. This editable outline gives an industrial project team a place to start.

Updated 17-Oct-2026

Twelve decisions to make together.

A BIM Execution Plan should describe this project, not a generic workflow. Use the outline to capture decisions with the client and discipline coordinators. If your appointment specifies ISO 19650 requirements, use those information requirements and the applicable standard when developing the project plan.

  1. Purpose and use

    What decisions must this model support? Identify coordination, drawing production, equipment layouts and any handover use. Do not assume a model is suitable for fabrication or operations unless that use is defined.

  2. People and responsibilities

    Name the information manager, discipline coordinators, model authors and approvers. State who makes decisions when disciplines conflict.

  3. Source information

    List surveys, existing models, 2D drawings and vendor information. Record the issue date and any known reliability limits.

  4. Coordinates and units

    Record the coordinate system, model origin, shared coordinates, units and responsibility for setting them. Agree how incoming models are checked.

  5. Required model content

    Define the elements each discipline will produce at each stage. Agree the level of development and information needed for each intended use.

  6. Naming and file exchange

    Set file naming, revision codes, native software versions and exchange formats. Include required title blocks and libraries.

  7. Model structure

    Agree discipline splits, worksets, links and the approach to federation. Make clear which model is the source for each element.

  8. Coordination reviews

    Set the review cadence, clash rules, priorities and ownership of actions. A clash report only helps if someone is responsible for resolving it.

  9. Technical queries

    Specify how missing inputs and conflicting information are raised, assigned and closed. Tie queries to the model or drawing reference.

  10. Checking and acceptance

    Define internal checking, client review, acceptance criteria and the review allowance. Agree how changes to the brief are handled.

  11. Information environment

    Record the common data environment, access permissions and issue process. Confirm confidentiality and file-sharing arrangements.

  12. Issue and handover

    List the native models, drawings, exchange files, revision information and any agreed asset data. Name the recipient and acceptance owner.
